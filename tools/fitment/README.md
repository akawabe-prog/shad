# 適合検索（tools/fitment）

商品マスター `data-source/ItemList_SHAD.csv` から、ブランドサイトの適合検索データを生成します。
生成ロジックは提供された `shad_site`（車種別適合検索）の実装をそのまま取り込み、
出力をブランドサイト向けに変換する工程（`postprocess.py`）を足した構成です。

## 使い方

```bash
python3 tools/fitment/build.py        # 生成 →（自動で postprocess も実行）
python3 tools/fitment/postprocess.py  # 商品との突合だけ再実行
```

出力（サイトが読むのはこの2本だけ）

| ファイル | 内容 |
|---|---|
| `site/data/fitment/reverse_data.json` | 車種463件 × 適合キット・商品、ベースプレート5種、サイドケース／サイドバッグ／タンクバッグ、クリックシステムキット |
| `site/data/fitment/product_index.json` | モデルコード → ベースプレート、サイド／バッグ／タンクの対象コード |

## 適合ロジック（提供実装のまま）

- **トップケース**：商品 → 付属ベースプレート → そのプレート対応のトップマスターキット → 適合車種
- **サイドケース／サイドバッグ**：3P／4P／サイドバッグホルダー／SRキットの「対応コード」に自コードを含む車種
- **タンクバッグ**：クリックシステムキットは1キットが複数メーカー・車種にまたがるため車種単位のマッチングは行わず、キット一覧を案内
- 廃番（CJ廃番=1）・セット品・アウトレット・非表示フラグの行は除外

## 商品との突合（postprocess.py）

`site/data/catalog/products.json`（`build_catalog.py` がマスターから生成）の
**品番 → モデルコード**の対応を使って、適合データ内の商品リンクを書き換えます。

| 項目 | 変換 |
|---|---|
| `url` | `moto.customjapan.net/i/品番` → `/product/<code>`（自サイトの商品ページ） |
| `ecUrl` | 元のECリンクを保持 |
| `img` | `/img/products/cards/<code>.webp`（一覧と同じ大きさ統一済みの画像） |
| `code` | モデルコードを付与 |

フィッティングキットとベースプレート単品は自サイトに個別ページが無いため、ECリンクのままです。

直近の突合結果：**商品SKU 59件すべてがカタログと一致し、40モデル全てに商品ページあり（書き換え73箇所）**。

## サイト側の実装

`site/js/fitment.js` の1本で全てを描画します。`data-fitment-mode` で挙動が変わります。

| 対象 | 器 | 挙動 |
|---|---|---|
| 入口（TOP） | `[data-fitment-finder][data-fitment-mode="entry"]` | 3段プルダウン＋キーワード検索のみ。車種を選ぶと「適合を見る」が有効になり、押すと `/fitment?bike=メーカー\|車種` へ遷移 |
| 結果ページ | `/fitment`（`data-fitment-mode="page"`） | 同じ検索UI＋TERRA／容量の絞り込み＋結果（トップケース／サイドケース／サイドバッグ／タンクバッグ）。URLの `?bike=` を復元し、選び直すと `history.replaceState` でURLも更新＝結果を共有できる |
| 商品ページ | `[data-product-fitment-checker]` | 「この商品が装着できる車種」。メーカー → シリーズ → 車種の3段プルダウンで選ぶと「装着できます」の判定と必要なキットを表示。全適合車種の一覧は折りたたみ（キーワード絞り込み付き）で確認できる |

サイト内の「For Your Motorcycle」「車種から探す」の導線はすべて `/fitment` に統一しています
（旧 `/#finder` からのリダイレクトも `.htaccess` に追加）。

デザインは当サイトのトーン（Barlow Condensed × Noto Sans JP／SHADレッド／mist）に
合わせて `css/custom.css` で再定義しています（提供実装のクラス名はそのまま使用）。

### 結果ページの絞り込み

- **カテゴリ**（チップ：すべて／トップケース／サイドケース／サイドバッグ／タンクバッグ）
  ＋ **TERRAシリーズのみ** ＋ **容量** の3つを併用できます
- カテゴリの判定は適合データの持ち方が根拠（ベースプレート配下＝トップケース、
  ハード／ソフトの別＝サイドケース／サイドバッグ、クリックシステム＝タンクバッグ）。
  `CATEGORY_OF`（型番→カテゴリ）を起動時に組み立てています
- 車種を選んでいる場合、サイドケースとサイドバッグは同じサイドキットに紐づくため
  1セクションで扱い、カテゴリを選ぶと見出しと「装着可能〜」の文言もその名前に変わります
- タンクバッグは車種専用キットが不要なので、車種選択中はカテゴリで
  「タンクバッグ」を選んだときだけ、その旨の案内付きで表示します

### 適合検索から商品ページへ来たとき

結果ページの商品カードは `/product/<code>?bike=メーカー|車種` へリンクします。
商品ページ側は `?bike=` があるとき、下部の「この商品が装着できる車種」を出さず、
**選んだ車種の判定だけ**を「適合確認はこちら」ボタンの位置に表示します
（他車種の一覧は不要なため）。

- 判定パネル：「〇〇 に装着できます」＋必要キット名＋「キットを見る」＋「適合検索の結果に戻る」
- `?bike=` の車種がその商品に適合しない場合、または適合データが読めない場合は、
  通常のプルダウン式セクションに自動で戻します
- タンクバッグは車種別の一覧ではなくキット一覧なので、`?bike=` 付きでもそのまま表示します
- `?bike=` 付きURLが重複ページ扱いにならないよう、商品ページに canonical を追加しています

### 結果ページの商品カード

商品一覧（`/products`）と同じ情報量・同じ見た目に揃えています。

- 表示内容：シリーズバッジ／型番／容量／カテゴリ名・色数／キャッチコピー／特徴アイコン3つ
- データ元：`site/data/catalog/cards.json`（`products.html` の `var PRODUCTS` が原本。
  `python3 tools/build_cards_json.py` で書き出し）。型番で引くため、コピーを直せば両ページに反映
- 並び順：容量の降順（可変容量は上限で比較、同容量は型番順）＝商品一覧と同じルール
- 適合データはカラー違いのSKU単位なので、カードは型番でまとめて1枚にしています
  （カラーは「2色」表記と商品ページで案内）。「ベースプレート付属」などの注記はカード下部に残ります
- カード情報が無い型番（マスター未登録など）は商品名だけの簡易カードに自動フォールバックします

## 特殊なキットの扱い

- **シーシーバー取付のトップマスターキット**（品番 17838535 ※プレート別 / NADTN ※プレート付）は
  商品名が「シーシーバー取付(レブル250/500/1100/エリミネーター/バルカンS)」の形で、
  以前は**これ自体が「車種」として車種プルダウンに出ていた**。現在は括弧内の車名を実在の
  車種に振り替えて、レブル250/500・レブル1100/CMX1100・エリミネーター/SE・バルカンS の
  各車種のトップキットとして表示する（`remap_mount_kit`）。
  なお、この4車種には通常のトップマスターキットはマスターに存在せず、シーシーバー取付のみ
- **装着できるトップケースは、キットの「仕様」欄の記載を正とする**（EC商品ページと同じ内容）。
  マスターの仕様欄には次のように書かれており、これを解析して一覧を作る。

  | キット | 仕様欄の記載 | 表示 |
  |---|---|---|
  | NADTN（シーシーバー取付 ※プレート付） | 対応ベースプレート：不要(フィッティングキットに直接取付)／対応モデル：SH26/SH29/SH33/SH34 | **4点**＋「ベースプレート不要」の注記 |
  | 17838535（同 ※プレート別） | 対応ベースプレート：D1B29PAR/D1B40PAR／対応モデル：SH26〜TR46（12点） | **12点** |
  | 10664353（BMW F650GS/G650GS） | 対応モデル：SHAD全てのトップケース＆TERRAシリーズに対応 | **全20点**＋「ベースプレート不要」 |

  仕様欄に記載が無いキット（365件中327件）は従来どおりベースプレート経由で導出する。
  記載があるのは38件で、うち2件は「ベースプレート不要」

## 引き継ぎ事項

- 旧システムで表示していた「この車種で使えるオプション（バックレスト／シーシーバー）」は
  車種IDの持ち方が変わったため一旦停止し、データを `tools/fitment/legacy/vehicle_options.json`
  に退避しています。新しい車種データ（maker＋model）に合わせて再照合すれば復帰できます。
- ~~TR50 は適合車種が出ない~~ → **解決済み**。TR50 の商品行はカテゴリが「シートバッグ」
  のためトップケース扱いされていなかったが、ベースプレート側のメーカータイプ
  （`TR37_TR48_TR50_TR55_…`）が対応を宣言しているので、**プレートの記載を正**として
  プレート配下に紐づけるようにした（`attach_topcases`）。336車種で表示される。
